# 骰子使用教程

> 本文按仓库当前骰子功能维护。结果数字只是示例，每次实际投掷都会重新生成。

骰子命令可在私聊和群聊中使用。骰式解析、随机数生成与计算都在 Core 本地完成；完整 `/roll` 的自然语言问题（可带显式骰式）才会先让 Entertainment DM 制定娱乐判定方案。

## 一分钟上手

```text
/roll
/roll 2d6
/r 1d20+3 开锁
/r 3#d6 生成三次结果
/roll 1d20+3 我能打开这扇门吗
.set coc
.r2#d+1
```

| 写法 | 作用 | 是否调用模型 |
| --- | --- | --- |
| `/roll` | 按当前规则投默认骰（DND 为 D20，CoC 为 D100） | 否 |
| `/roll 2d6` | 按骰式本地投掷 | 否 |
| `/r 1d20+3 开锁` | 本地投掷，“开锁”只作为结果中的原因 | 否 |
| `/roll 晚上要不要出门` | 用当前规则的默认骰做 Entertainment DM 判定（DND 为 D20，CoC 为 D100） | 是 |
| `/roll 2d6+1 我能跳过沟吗` | 用指定骰式做 Entertainment DM 判定 | 是 |

最重要的区别是：`/r`、`/rd` 后面的文字永远是本地骰点原因；只有完整命令 `/roll` 的自然语言问题才会进入 Entertainment DM。

熟悉 SealDice 的用户可以用 `.set dnd` 或 `.set coc` 切换当前会话的默认骰面数：DND 模式下裸 `d` 为 D20，CoC 模式下裸 `d` 为 D100。该设置会持久化，并按当前私聊或群聊 conversation 隔离。

## 骰子表达式

基础格式是 `NdM`：`N` 表示骰子数量，`M` 表示面数。省略 `N` 时按一个骰子处理。

| 需求 | 示例 | 说明 |
| --- | --- | --- |
| 一个二十面骰 | `d20` | 等价于 `1d20` |
| 当前默认骰 | `d` | DND 模式为 `d20`，CoC 模式为 `d100` |
| 两个六面骰 | `2d6` | 两个结果相加 |
| 固定修正 | `1d20+3`、`2d6-1` | 支持正负修正 |
| 多段骰子 | `1d8+1d6+4` | 不同面数可以组合 |
| 四则运算 | `(2d6+3)*2` | 支持 `+`、`-`、`*`、`/` 和括号 |
| 幂运算 | `d6**2` | 使用 `**`，指数最大为 12 |

除法使用整数运算。建议跑团时优先使用简单、容易复核的表达式。

## 取骰、优势与劣势

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `kN`、`khN` | 保留最高的 N 个 | `4d6k3` |
| `qN`、`klN` | 保留最低的 N 个 | `2d20q1` |
| `dhN` | 丢弃最高的 N 个 | `4d6dh1` |
| `dlN` | 丢弃最低的 N 个 | `4d6dl1` |
| `d20优势` | 投两个 D20，取高 | 等价于 `2d20k1` |
| `d20劣势` | 投两个 D20，取低 | 等价于 `2d20q1` |

数量 `N` 省略时默认为 1，例如 `d20kh` 等价于 `d20kh1`。优势或劣势后还可以继续加修正，例如 `/rd优势+6+1d4`。

## 重复投掷

使用 `次数#骰式` 一次生成多轮独立结果：

```text
/r 3#d20 侦查
/r 5#2d6
.r2#d+1
```

重复次数为 1–20，一条命令实际投出的骰子总数不能超过 200。Entertainment DM 只支持单次判定，因此 `/roll 3#d20 问题` 会被明确拒绝；需要多轮结果时使用 `/r`。

## 奖励骰与惩罚骰

`b` / `bN` 表示百分骰奖励骰，`p` / `pN` 表示百分骰惩罚骰，`N` 默认为 1、最大为 20。

```text
/r b 调查
/r p2 聆听
/rab 调查
/rap 聆听
```

`/rab` 是单个奖励骰快捷命令，`/rap` 是单个惩罚骰快捷命令；尾随文字仍然只是本地原因，不调用模型。

## SealDice 常见写法

默认命令前缀下兼容以下紧凑形式：

```text
/r2d6
/rd20
/rd优势+6
.r2d6
.rd劣势
。rap 聆听
.set dnd
.set coc
```

`/r`、`/rd`、`/rap`、`/rab` 均可使用；半角句点 `.` 和全角句点 `。` 也兼容常见骰点入口。紧凑写法可以直接连接中文原因，例如 `.r2d6说服守卫`。

`.set dnd` 会把裸 `d` 与无参数 `/r` 设为 D20，Entertainment DM 使用“点数 ≥ DC”判断成功；`.set coc` 会改为 D100，并使用“点数 ≤ 目标值”判断成功。两种模式都只影响轻量骰点与 Entertainment DM，不代表已经启用完整 DND5E / CoC7 人物卡或规则扩展。

当 Entertainment DM 发生 Provider 错误、超时或返回非法结构化方案时，Core 会在本地使用本轮实际解析出的骰式完成 fallback，不会伪造判定成功。未显式指定骰式时，fallback 使用当前规则的默认骰，并从实际 `RollResult` 显示对应骰面（DND 为 D20，CoC 为 D100）；显式指定骰式时，仍保留“指定骰子表达式投掷”的原有文案和投掷语义。

如果部署者把 `command.prefix` / `CHAT_COMMAND_PREFIX` 改为 `#` 或 `*`，普通命令应改用配置后的前缀，旧 `/` 与点号不再作为通用命令前缀；是否保留某种 SealDice 紧凑写法，应以当前机器人的 `/help roll` 返回为准。

## 基础先攻（Phase 2.5）

无需人物卡或 Campaign，即可共享当前群／私聊会话的先攻表：

```text
/ri 12 张三
/ri +2 李四
/ri =d10+3 王五
/ri d20+4 哥布林
/ri d20+4
/ri 张三, +2 李四, =d10+3 王五
/ri+5 哥布林1，+2 哥布林2
/ri 优势 张三, 劣势-1 李四
/init
/init set 哥布林 d20+2
/init del 哥布林
/init end
/init clr
```

`/ri` 的数字为固定先攻，`+N`／`-N` 使用 D20 加修正，`=expr` 使用指定单轮骰式，裸骰式（如 `d20+4`）使用解析出的完整表达式；优势／劣势使用两个 D20 取高／低。默认命令前缀下，`/ri+5 哥布林` 是 `/ri +5 哥布林` 的 SealDice 风格紧凑写法，`.ri+5 哥布林` 也兼容；只有 `ri` 后紧接 `+` 或 `-` 时才按紧凑先攻识别，不会把 `/rich`、`/right` 当作先攻命令。骰式后可直接跟单位名，例如 `/ri d20+4 哥布林`；只写名称时投 D20，省略名称时沿用 `/set 昵称`、`/nn` 或平台展示名，都不可用时提示显式命名。先攻始终默认 D20，不受 `.set coc` 影响。

名称区分大小写，长度 1–64 字，不含空格或逗号。同名覆盖；一次最多 20 个单位、200 颗骰子，一张表最多 100 个单位。批量输入失败时整批不写入。同值按名称 Unicode 顺序稳定排序；群、平台和机器人账号沿用 conversation scope 隔离。同群所有玩家都能维护此表。

首轮从最高先攻者开始，首次 `end` 前录入单位会重新选择最高者；推进后添加／修改单位保留当前行动者，之后按新排序继续。每次 `end` 前进一位，回到表首时轮数加一。删除当前者选择删除前顺序中下一个仍在表中的单位，绕回表首时轮数加一；删除最后一个单位或 `clr` 重置全部轮次。重启程序清空临时先攻状态，不产生数据库 migration。

`/init list` 等同 `/init`；支持 `rm`（del）、`ed`（end）、`clear`（clr）。`/initclr` 等同 `/init clr`，清空先攻表并重置当前行动状态和回合数；默认前缀下也可使用 `.initclr`。不支持的子命令明确返回帮助。

## 暗骰与代骰入口

`/rh d20+3 侦查` 在私聊直接返回本地结果；OneBot 群聊在 Gateway 提供可信私发地址时，将结果写入统一 Notification Outbox，由 Worker 私发给发言人。群内只回执“已进入私发队列”，不包含结果或原因，也不声称已经送达。请确保机器人能够私聊该用户；投递失败沿用 Outbox 的重试和终态记录。

QQ 官方群聊的群成员 openid 不能直接当成 C2C 地址；缺少可信私发目标时拒绝投骰，不会在群里公开暗骰结果。可改为私聊 `/rh`。支持 `/rhd`、`/rdh` 别名以及紧凑 `/rhd20`。

`/rx`、`/rxh`、`/rhx` 已建立确定性命令边界，目前明确提示人物卡／被代骰者上下文尚未接入，不投骰、不进入 AI；无状态投掷可使用 `/r`。

兼容语义核对来源：[SealDice DND5E 命令实现](https://github.com/sealdice/sealdice-core/blob/cd870ebcf97fa558e7983fa86e5bd8a5f973859d/dice/ext_dnd5e.go)和[基础骰点／代骰命令实现](https://github.com/sealdice/sealdice-core/blob/cd870ebcf97fa558e7983fa86e5bd8a5f973859d/dice/builtin_commands.go)。本阶段保留本项目的有界骰式引擎，未复制人物属性解析或平台代理身份逻辑。

## Entertainment DM

只有下面两类完整 `/roll` 写法会进入 Entertainment DM：

```text
/roll 我今晚能抽到想要的角色吗
/roll 1d20+5 我能说服守卫开门吗
```

模型只在投掷前选择检定名称、娱乐难度与成功/失败含义，看不到实际骰值，也不负责计算 DC。Core 会根据骰式的理论范围计算 DC，再在本地生成骰值并确定结果。

这不是 DND5E、COC 或其他正式规则系统。当前项目没有 Campaign / Rule Context，Entertainment DM 使用统一的六档娱乐刻度；`.set dnd` / `.set coc` 只切换轻量骰点的默认骰面数和判定方向。Provider 出错、超时或返回非法方案时，机器人会明确回退为指定骰式或当前规则默认骰的普通本地投掷，不会伪造判定成功。

## 限制与排错

| 限制 | 当前值 |
| --- | --- |
| 单个骰子段的骰子数量 | 1–100 |
| 骰子面数 | 1–100 |
| 单个表达式的骰子段 | 最多 8 段 |
| 单个表达式实际骰子总数 | 最多 100 |
| 重复次数 | 1–20 |
| 一条命令实际骰子总数 | 最多 200 |
| 表达式长度 | 最多 64 个字符 |
| 整数与修正值绝对值 | 最大 1000 |
| 本地原因或 DM 问题 | 最多 500 个字符，不支持换行或控制字符 |

收到“骰子表达式无效”时，先检查是否使用了 `0d6`、`d0`、超过范围的数量或面数、除以零、过深括号，或项目尚未支持的 SealDice 扩展语法。未知语法不会交给模型猜测，也不会伪造骰点结果。

机器人内置的简版说明可通过 `/help roll` 查看。
