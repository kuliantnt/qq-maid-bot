# 骰子使用教程

> 本文按当前 `master` 的 v0.24.4 骰子功能维护。结果数字只是示例，每次实际投掷都会重新生成。

骰子命令可在私聊和群聊中使用。骰式解析、随机数生成与计算都在 Core 本地完成；完整 `/roll` 的自然语言问题（可带显式骰式）才会先让 Entertainment DM 制定娱乐判定方案。

## 一分钟上手

```text
/roll
/roll 2d6
/r 1d20+3 开锁
/r 3#d6 生成三次结果
/roll 1d20+3 我能打开这扇门吗
.set coc
.r2#d+1
```

| 写法 | 作用 | 是否调用模型 |
| --- | --- | --- |
| `/roll` | 按当前规则投默认骰（DND 为 D20，CoC 为 D100） | 否 |
| `/roll 2d6` | 按骰式本地投掷 | 否 |
| `/r 1d20+3 开锁` | 本地投掷，“开锁”只作为结果中的原因 | 否 |
| `/roll 晚上要不要出门` | 用当前规则的默认骰做 Entertainment DM 判定（DND 为 D20，CoC 为 D100） | 是 |
| `/roll 2d6+1 我能跳过沟吗` | 用指定骰式做 Entertainment DM 判定 | 是 |

最重要的区别是：`/r`、`/rd` 后面的文字永远是本地骰点原因；只有完整命令 `/roll` 的自然语言问题才会进入 Entertainment DM。

熟悉 SealDice 的用户可以用 `.set dnd` 或 `.set coc` 切换当前会话的默认骰面数：DND 模式下裸 `d` 为 D20，CoC 模式下裸 `d` 为 D100。该设置会持久化，并按当前私聊或群聊 conversation 隔离。

## 骰子表达式

基础格式是 `NdM`：`N` 表示骰子数量，`M` 表示面数。省略 `N` 时按一个骰子处理。

| 需求 | 示例 | 说明 |
| --- | --- | --- |
| 一个二十面骰 | `d20` | 等价于 `1d20` |
| 当前默认骰 | `d` | DND 模式为 `d20`，CoC 模式为 `d100` |
| 两个六面骰 | `2d6` | 两个结果相加 |
| 固定修正 | `1d20+3`、`2d6-1` | 支持正负修正 |
| 多段骰子 | `1d8+1d6+4` | 不同面数可以组合 |
| 四则运算 | `(2d6+3)*2` | 支持 `+`、`-`、`*`、`/` 和括号 |
| 幂运算 | `d6**2` | 使用 `**`，指数最大为 12 |

除法使用整数运算。建议跑团时优先使用简单、容易复核的表达式。

## 取骰、优势与劣势

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `kN`、`khN` | 保留最高的 N 个 | `4d6k3` |
| `qN`、`klN` | 保留最低的 N 个 | `2d20q1` |
| `dhN` | 丢弃最高的 N 个 | `4d6dh1` |
| `dlN` | 丢弃最低的 N 个 | `4d6dl1` |
| `d20优势` | 投两个 D20，取高 | 等价于 `2d20k1` |
| `d20劣势` | 投两个 D20，取低 | 等价于 `2d20q1` |

数量 `N` 省略时默认为 1，例如 `d20kh` 等价于 `d20kh1`。优势或劣势后还可以继续加修正，例如 `/rd优势+6+1d4`。

## 重复投掷

使用 `次数#骰式` 一次生成多轮独立结果：

```text
/r 3#d20 侦查
/r 5#2d6
.r2#d+1
```

重复次数为 1–20，一条命令实际投出的骰子总数不能超过 200。Entertainment DM 只支持单次判定，因此 `/roll 3#d20 问题` 会被明确拒绝；需要多轮结果时使用 `/r`。

## 奖励骰与惩罚骰

`b` / `bN` 表示百分骰奖励骰，`p` / `pN` 表示百分骰惩罚骰，`N` 默认为 1、最大为 20。

```text
/r b 调查
/r p2 聆听
/rab 调查
/rap 聆听
```

`/rab` 是单个奖励骰快捷命令，`/rap` 是单个惩罚骰快捷命令；尾随文字仍然只是本地原因，不调用模型。

## SealDice 常见写法

默认命令前缀下兼容以下紧凑形式：

```text
/r2d6
/rd20
/rd优势+6
.r2d6
.rd劣势
。rap 聆听
.set dnd
.set coc
```

`/r`、`/rd`、`/rap`、`/rab` 均可使用；半角句点 `.` 和全角句点 `。` 也兼容常见骰点入口。紧凑写法可以直接连接中文原因，例如 `.r2d6说服守卫`。

`.set dnd` 会把裸 `d` 与无参数 `/r` 设为 D20，Entertainment DM 使用“点数 ≥ DC”判断成功；`.set coc` 会改为 D100，并使用“点数 ≤ 目标值”判断成功。两种模式都只影响轻量骰点与 Entertainment DM，不代表已经启用完整 DND5E / CoC7 人物卡或规则扩展。

当 Entertainment DM 发生 Provider 错误、超时或返回非法结构化方案时，Core 会在本地使用本轮实际解析出的骰式完成 fallback，不会伪造判定成功。未显式指定骰式时，fallback 使用当前规则的默认骰，并从实际 `RollResult` 显示对应骰面（DND 为 D20，CoC 为 D100）；显式指定骰式时，仍保留“指定骰子表达式投掷”的原有文案和投掷语义。

如果部署者把 `command.prefix` / `CHAT_COMMAND_PREFIX` 改为 `#` 或 `*`，普通命令应改用配置后的前缀，旧 `/` 与点号不再作为通用命令前缀；是否保留某种 SealDice 紧凑写法，应以当前机器人的 `/help roll` 返回为准。

## Entertainment DM

只有下面两类完整 `/roll` 写法会进入 Entertainment DM：

```text
/roll 我今晚能抽到想要的角色吗
/roll 1d20+5 我能说服守卫开门吗
```

模型只在投掷前选择检定名称、娱乐难度与成功/失败含义，看不到实际骰值，也不负责计算 DC。Core 会根据骰式的理论范围计算 DC，再在本地生成骰值并确定结果。

这不是 DND5E、COC 或其他正式规则系统。当前项目没有 Campaign / Rule Context，Entertainment DM 使用统一的六档娱乐刻度；`.set dnd` / `.set coc` 只切换轻量骰点的默认骰面数和判定方向。Provider 出错、超时或返回非法方案时，机器人会明确回退为指定骰式或当前规则默认骰的普通本地投掷，不会伪造判定成功。

## 限制与排错

| 限制 | 当前值 |
| --- | --- |
| 单个骰子段的骰子数量 | 1–100 |
| 骰子面数 | 1–100 |
| 单个表达式的骰子段 | 最多 8 段 |
| 单个表达式实际骰子总数 | 最多 100 |
| 重复次数 | 1–20 |
| 一条命令实际骰子总数 | 最多 200 |
| 表达式长度 | 最多 64 个字符 |
| 整数与修正值绝对值 | 最大 1000 |
| 本地原因或 DM 问题 | 最多 500 个字符，不支持换行或控制字符 |

收到“骰子表达式无效”时，先检查是否使用了 `0d6`、`d0`、超过范围的数量或面数、除以零、过深括号，或项目尚未支持的 SealDice 扩展语法。未知语法不会交给模型猜测，也不会伪造骰点结果。

机器人内置的简版说明可通过 `/help roll` 查看。
