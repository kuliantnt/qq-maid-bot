# Agent 工具成功后追加错误的排查与回归

## 已确认的代码路径

本次使用脚本化 `AgentStepSession` 驱动生产 `run_agent_loop`、`ToolRegistry`、
Train/Search Tool 和 Respond 投影/拼装。查询 executor 使用公开测试夹具，不访问
真实铁路或搜索服务，不读取线上日志、配置或聊天记录。因此下述计数属于可控复现，
不能直接作为某次线上请求的计数。

| 模型请求 | 模型输出 | Tool 内部行为 | 查询后端累计请求 |
| --- | --- | --- | --- |
| 1 | Train(K349, 2026-09-10) | 校验成功，取得测试时刻表 | 1 |
| 2 | Train(仅保留相同日期，丢失车次) | `parse_train_code` 返回 `bad_tool_arguments` | 1 |
| 3 | 最终回答 | 不再调用工具 | 1 |

合计 **3 轮模型请求、2 次 Tool Call、2 次进入 Tool、1 次实际查询**。
Search 的 `query -> {}` 复现具有相同计数；其参数错误由
`WebSearchArgumentError::agent_output` 产生，编码为 `invalid_arguments`。

首次错误并非 formatter 凭空制造：模型第二次给出退化参数，业务 Tool 校验失败，
执行器把失败保存到 `tool_results` 并回填模型。Train presenter 再把结构化错误码
转换为“火车查询参数不完整”错误块。旧通用投影只识别失败后的重试覆盖，无法识别
成功之后的冗余续调，因此将两个结果都视为独立结果；composition 选择确定性回退，
渲染成功事实卡和错误块。视觉上像“在正确回答后追加错误”，实际可以是整轮重新拼装。

工具成功后继续请求模型是正常的多步任务协议：模型需要总结结果，也可能执行新步骤。
`runner` 只有轮数或预算等条件才禁用后续工具调用；不能仅因某个工具成功就终止任务。
当前代码检查与脚本复现不能证明线上模型为什么生成了该次缺参调用，也不能证明
线上 Search 超时一定属于重复调用。

另一个已确认问题是成功只读缓存命中返回紧凑 `{"ok":true,"deduplicated":true}`。
Search 已能隐藏该类结果，Train 却会因其中没有时刻表字段而生成解析失败错误块。

## 修复边界

通用执行器为调用轨迹增加 `redundant_of`，指向已有结果，原始成功/失败值保持不变：

- 同请求只读缓存命中直接关联原结果，不将紧凑回执再次解释成领域数据。
- 对参数错误，只有连续单例只读调用、已有未截断成功结果、当前参数是原参数的
  退化子集且没有新增/改变的非空信息时，才建立续调关联。连续冗余调用保留同一锚点。
- 新目标、新日期、新选项、批量调用、写操作、超时、未知错误及无法解析的 JSON
  不因已有成功而被隐藏。首轮缺参仍然报告；实际第二步超时仍为部分失败。
- 退化调用的回填仍为 `ok=false`，附带纠正提示，让模型基于已有结果总结，或补全
  必要新步骤的参数再调用；不禁止同一工具继续调用，不把未执行的新步骤声明为成功。
- 通用投影与 Search 整轮统计消费服务端调用关系，不过滤用户文案。
  候选切换时关联下标按 baseline 转为全局下标，不能跨候选猜测续调关系。

没有新信息的缺参调用无法单凭参数证明其自然语言意图；这里采用明确、保守的
退化子集规则。新任务身份无法确认、非连续调用或协议解析错误仍保留失败。
该修复不保证模型不会自行在最终正文编造错误，也不隐藏真实网络超时。

## 可重复验证

```bash
cargo test -p qq-maid-core runtime::respond::tests::agent_turn::continuation
cargo test -p qq-maid-llm agent_loop::tests::continuation
make test-llm
make test
```

Core 回归通过真实 Tool/Loop 生成轨迹，再送入 Respond 投影/拼装；同时移除 Train
轨迹中的新关联，验证旧语义确实会得到“时刻表 + 错误块”。覆盖首次缺参、成功后缺参、
相同查询缓存命中、改变日期后缺参，以及 Train/Search 必要第二步超时。
LLM 回归覆盖空/null/空白参数、不同选项、副作用、批量调用、连续退化、继续执行必要
步骤及候选切换下标。各场景显式断言模型轮数、Tool Call 数和执行结果。

真实环境应使用脱敏响应诊断中的 `agent_model_rounds`、`agent_emitted_tool_count`、
`agent_executed_tools`、新增 `agent_tool_attempts`（含 `round`、`result_index`、`retry_of`、`redundant_of`）核对调用关系。
新增日志只包含工具名、轮次与结果下标，不输出参数或用户正文。
